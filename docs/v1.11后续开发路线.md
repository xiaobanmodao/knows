# 知识通 v1.11 后续开发路线

> 路线状态：规格已确认，实施从 `codex/roadmap-v1.11` 开始
>
> 当前运行版本：`1.10.1-dev.1`
>
> 发布分支：`codex/release-regression-v1.10.1`

## 1. 目标与边界

v1.11 的目标是把五科学科内容维护变成可重复、可核对、可回归的开发流程，重点解决教材来源映射、内容复核和发布前差异控制。v1.11 不以新增页面或增加学习任务为目标。

产品继续保持纯知识查阅：不加入在线测评、自动评分、学完自测、单元输出任务、错题本、打卡、家长端、强制登录、云同步或未经人工审核的 AI 讲解。

本路线不改变现有稳定 ID、云资源路径、本地存储版本或备案信息。教材照片、自有教辅和公开资料只用于核对课程边界与知识关系，正文、例句、示例、解析和插图继续原创整理。

### 2.2 运行与发布规格

- 主包、数学、英语、物理、化学和生物继续按普通分包运行，公共组件和轻量搜索索引留在主包。
- 内容仓库继续使用静态 JavaScript，构建期生成搜索索引、审计报告和资源清单。
- 本地记录继续使用 `subjectId:type:id`，不因路线文档升级存储版本。
- 云图片失败时必须保留完整文字内容；未准备好云环境时不得调用无效云接口。
- 运行时版本在 v1.10.1 发布闭环前保持 `1.10.1-dev.1`；不在路线分支提前伪造 `1.11.0` RC。

## 4. 阶段 1：v1.11 来源地图与内容维护

### 4.1 数学新版目录映射

数学新版教材的处理顺序固定为：官方目录证据收集 -> 结构差异报告 -> 稳定 ID 映射 -> 页面显示核对 -> 回归检查。

已公开确认的结构变化可以记录为映射；未取得逐册官方目录时，必须保留 `needs-official-volume-map` 边界。不得因为目录顺序变化而：

- 直接用章节序号重建主键；
- 批量重命名 `ch*`、专题、知识点或模板稳定 ID；
- 删除现有章节或将历史内容强行归入猜测的新版章节；
- 用搜索结果、培训机构目录或单张教材照片替代官方逐册证据。

每个完成的映射至少记录：稳定 ID、教材版本、册次、显示标题、官方小节、来源 URL/PDF、核对日期、变更原因和是否影响旧别名。

### 4.2 英语教材映射

英语五册现有单元和详细词法/语法内容继续保持可查阅。人教社公开介绍已确认九年级下册有 5 个正式学习单元和 2 个选学戏剧；本轮再核对人教社官方数字配套资源入口后，仍未取得九下具体标题。只有在正式目录、单元标题和可靠教材文件完成交叉核对后才扩充。此前只记录结构待核对项，不创建空单元、不编造单元标题、不把能力专题伪装成教材单元。

已有词条和语法点的维护必须保留英式主拼写、美式变体、IPA、词性、可数性/及物性、搭配、原创例句、辨析和复核来源字段。

### 4.3 物理、化学和生物维护

按小批次复核以下高风险字段：

- 物理：符号、单位、方向、公式条件、实验步骤、误差、安全提醒和图示连线；
- 化学：化学式、反应条件、配平、实验现象、结论和图片文字降级；
- 生物：术语、观察对象、实验步骤、结论、单元父级和窄屏文字布局。
- 生物来源已补齐教育部课程标准和人教社七至八年级新教材介绍两条稳定 `sourceRefs`，后续新增生物批次继续沿用同一格式。

每次只处理一个明确批次，完成后立即生成差异报告和检查结果。内容准确性问题与页面交互问题分开提交，避免难以定位回归来源。

## 5. 阶段 2：内容生产与审计底座

在阶段 1 的来源地图稳定后，再逐步建设：

1. 结构化内容输入格式，支持稳定 ID、父级、别名、来源和复核状态；
2. 构建期 schema 校验、搜索索引生成、图片资源检查和差异报告；
3. 人工复核队列，区分待核对、已核对和已发布状态；
4. 小批次内容预览，确保正文、图示和搜索结果同时可回归。

当前已先完成元数据目录阶段：`scripts/build-content-source-catalog.js` 生成 `dist/content-audit/content-source-catalog.json`，`scripts/check-content-source-catalog.js` 校验源哈希、父级引用、旧别名和禁止正文字段，并支持通过 `CONTENT_SOURCE_CATALOG_BASELINE` 输出新增/修改/删除差异、通过 `--require-no-diff` 作为阻断门禁。输入协议由 `scripts/content-source-input.js` 负责 JSON/CSV 行归一化，`scripts/build-content-source-input.js` 生成带 `inputHash` 的规范化 JSON，支持 `--from-current --batch <batchId>` 按登记批次导出；`scripts/check-content-source-input.js --batch <batchId> --report <report.json>` 可对单个外部 JSON/CSV 输入校验范围、统计和差异，并留存输入哈希、当前源哈希、复核统计和变更明细。新增 `scripts/check-content-source-input-batches.js` 支持用 manifest 一次登记多个外部批次，逐批读取 JSON/CSV、输出 `passed/changed/pending/failed` 报告；默认模式允许先查看缺失或变更，拿到完整外部资料后使用 `--require-all-batches --require-no-diff` 作为批次差异阻断门禁。manifest 保存 `schemaVersion`、`sourceVersion`、`sourceKind` 和批次级 `{ id, path, sourceKind, inputHash? }`；外部 manifest 由 `scripts/build-content-source-external-manifest.js` 读取并规范化输入文件后写入 `inputHash`，后续文件被替换或修改会以 `manifest-input-hash-mismatch` 失败，旧 manifest 没有该字段时保持兼容。其中当前源导出固定为 `current-fixture`，旧 manifest 读入为 `unknown`；`--require-external-source` 会逐批要求 `external-source`，因此不能只改 manifest 顶层字段绕过门禁，路径必须相对 manifest 文件。示例命令为 `node scripts/check-content-source-input-batches.js <manifest.json> --report <report.json> --require-all-batches --require-no-diff --require-external-source`。新增 `scripts/build-content-source-input-manifest.js` 可自动导出当前 23 个登记批次的规范化 JSON 和相对路径 manifest；`node scripts/build-content-source-input-manifest.js` 后再执行普通严格审计可完成当前源的端到端干跑，但该夹具不等同于外部资料复核证据，且不能通过外部来源门禁。`scripts/check-content-source-batches.js` 固化全部 23 个学科/类型批次的实体数量、类型隔离、示例/实验/资源统计、复核状态和零差异要求，并可通过 `--report dist/content-audit/content-source-batches.json` 生成确定性批次报告。新增 `scripts/check-subject-high-risk-batches.js` 登记英语 5 册和物理 3 册共 8 个高风险批次，逐批校验词法/语法补深、物理公式契约、单位、方向、实验和复核状态，并生成 `dist/content-audit/subject-high-risk-batches.json`；新增 `scripts/check-chemistry-biology-high-risk-batches.js` 按化学 5 个主题批次和生物 6 个专题批次登记高风险字段，逐批校验化学方程式/实验、生物观察/例子和复核状态，并生成 `dist/content-audit/chemistry-biology-high-risk-batches.json`。当前批次审计覆盖 948 个实体、1,987 个示例、49 个实验和 1,885 个资源，复核状态为 900 个 verified、48 个 reviewed；旧别名仍由内容源目录校验。这些产物只服务构建审计，不改变运行时数据来源。

严格内容审计同时要求 URL 来源带稳定 key，并拒绝同一 key 对应多个 URL；当前 1,963 条来源引用中 URL-only 引用为 0。

来源键统一登记在 `data/content-source-registry.js`；审计会检查五科实体引用和数学目录基线是否可解析、官方/参考来源是否具备标题和规范 URL，以及同一来源键的 URL 是否发生漂移。注册表只服务构建期校验，不进入小程序主包或分包。

当使用 `--require-external-source` 时，批次工具会先写出报告，再以非零退出码阻断非 `external-source` 批次；报告中的 `requirements.externalSourceIssues` 会列出批次 ID、输入路径、实际 `sourceKind` 和阻断原因。使用 `--require-reviewed` 时，报告还会检查每个已读入批次的 `review.untracked`，并在 `requirements.reviewIssues` 中列出未人工复核的实体。这样可以直接把报告交给下一轮资料接入，不需要从终端异常中手工恢复缺口。

资料接入前可先生成执行顺序报告：`node scripts/build-content-source-follow-up.js dist/content-audit/content-source-input-batches/manifest.json --report dist/content-audit/content-source-follow-up.json`。报告按“修复输入 -> 补齐复核状态 -> 接入外部来源 -> 复核差异 -> 补齐文件”排序；同等处理动作下优先展示已有输入文件的批次，`summary.nextBatchId` 给出当前最先处理的批次。每个批次同时输出 `sourceRequirements`，列明官方来源候选、必须保留的证据字段和禁止动作；路线状态命令会把下一批次的证据说明带入下一步提示。报告同时保存 manifest、当前源和批次输入哈希，避免资料更新后误用旧报告。生成后运行 `node scripts/check-content-source-follow-up.js <manifest.json> <report.json>` 重建并比对报告；`--require-ready` 仅在全部批次具备外部来源、没有 `untracked` 且没有其他待处理项时作为阻断门禁。

为减少资料接入时的人工整理，`node scripts/build-content-source-intake-pack.js dist/content-audit/content-source-follow-up.json --report dist/content-audit/content-source-intake-pack.json` 会把全部批次的稳定 ID、当前状态、优先级、官方来源候选、必填证据字段、当前差异和预期统计导出为接入包。接入包中的 `sourceEvidenceTemplate` 只包含空占位字段，不是外部来源凭证，也不能替代 manifest 审计；取得真实官方资料后，仍须使用 `build-content-source-external-manifest.js` 生成带输入哈希和来源凭证的 manifest。质量矩阵会先重建当前源 manifest 和跟进报告，再校验并生成接入包，避免使用旧的 `dist` 产物。

取得真实外部 manifest 后，可按需运行 `node scripts/check-content-source-url-access.js <manifest.json> --report dist/content-audit/content-source-url-access.json --require-accessible` 检查来源链接是否可访问，并记录 HTTP 状态和最终跳转地址。该检查不进入默认构建矩阵，避免网络波动影响本地确定性构建；默认矩阵只验证其报告契约和无来源/严格模式行为。

若已生成 URL 报告，可通过 `node scripts/check-roadmap-status.js --url-access-report <report.json> --url-access-manifest <manifest.json>` 将失败链接和报告过期状态纳入路线汇总；报告的 manifest 哈希与当前输入不一致时会提示重新生成。未提供 URL 报告时，路线状态显示为 `not-run`，不把尚未执行的按需检查误报为失败。

外部来源批次除了 `sourceKind: "external-source"`，还必须在批次项中提供 `sourceEvidence`：至少包含非空 `sourceKeys`、一个可解析的 `reviewedAt`、一个真实的 `http/https` 来源 URL 和 `note`；每个 `sourceKey` 还必须实际出现在导入实体的复核来源中。输入文件的 `sourceVersion` 也不得等于当前源版本 `v1.11-current`；缺少凭证、来源键未被实体引用、缺少来源 URL、使用 `example.com`/`.invalid` 等占位 URL、仅把批次改成 `external-source`，或继续使用当前源版本，都会在 `--require-external-source` 下阻断，防止用当前源导出文件冒充外部复核材料。外部 manifest 构建器会在生成前直接拒绝当前源版本或未被实体引用的来源键。

首批外部输入可用 `scripts/build-content-source-external-manifest.js` 登记。工具只写 manifest，不修改输入文件：

```bash
node scripts/build-content-source-external-manifest.js \
  --batch english-units-v1.11 \
  --input /path/to/english-units.json \
  --manifest dist/content-audit/external-english-units-manifest.json \
  --source-key pep-english-new-textbook-2025 \
  --source-url https://www.pep.com.cn/xw/zt/hd/12/xjcjs/cz/202510/t20251024_2004130.html \
  --reviewed-at 2026-08-10 \
  --note "记录本批外部资料和复核范围"
```

运行时仍加载构建产物，不把数据库、后台编辑器、登录或云同步引入 v1.11 的第一批任务。

## 6. 分支与提交规则

### 发布分支

`codex/release-regression-v1.10.1` 只接受以下变更：发布配置、包体/设备证据工具、云运行时阻塞修复、与发布直接相关的文档。未通过严格门禁前，不创建 RC。

### 路线分支

`codex/roadmap-v1.11` 用于路线文档、来源地图工具和后续内容维护。路线分支不代替发布分支的实体设备证据，也不把未发布内容上传为正式体验版。

### 热修复分支

如果 v1.10.1 实体回归发现问题，从最终冻结提交建立独立 `codex/release-hotfix-*` 分支。热修复只包含复现所需的最小改动，不合并 v1.11 内容。

### 单批提交顺序

```text
规格/来源记录 -> 数据或工具实现 -> 页面适配 -> 校验与差异报告 -> 文档 -> 回归结果
```

每个提交保持一个可解释主题；不要把大批量内容改写、图片替换和路由重构放进同一提交。
