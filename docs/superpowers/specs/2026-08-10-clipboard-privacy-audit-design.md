# 剪贴板隐私接口审计设计

> 状态：已实现并接入 v1.11 质量矩阵
>
> 日期：2026-08-10

## 背景

微信开发者工具会检测 `Clipboard` 隐私接口。当前项目提供知识内容复制、备份文本复制和备案查询地址复制功能，这些操作都由用户主动点击触发。项目没有读取剪贴板的需求，也不应在页面生命周期、启动流程或后台读取剪贴板内容。

## 目标

1. 保留当前复制功能和用户交互，不改运行时行为。
2. 以构建期检查固定剪贴板调用边界，禁止 `wx.getClipboardData`。
3. 明确登记每个 `wx.setClipboardData` 调用点和用途，新增调用必须同步更新清单。
4. 形成可用于隐私指引的准确说明：仅在用户主动点击复制或备份操作后，将当前页面内容写入系统剪贴板；不读取剪贴板、不在后台访问、不上传剪贴板内容。

## 方案

新增构建脚本 `scripts/check-privacy-interfaces.js` 和对应测试。检查器扫描运行时源码目录，忽略测试、构建产物和生成的搜索索引，并输出确定性的接口报告：

```js
{
  clipboard: {
    readCalls: 0,
    writeCalls: 8,
    allowedFiles: [...]
  },
  status: 'passed'
}
```

允许文件及用途固定为：

- `components/content-block/index.js`：复制单个知识内容块；
- `pages/profile/index.js`：复制备份文本和备案查询地址；
- `packages/math/pages/knowledge/index.js`：复制数学知识核心内容；
- `packages/english/pages/knowledge/index.js`：复制英语知识核心内容；
- `packages/physics/pages/knowledge/index.js`：复制物理知识核心内容；
- `packages/chemistry/pages/knowledge/index.js`：复制化学核心知识；
- `packages/biology/pages/knowledge/index.js`：复制生物核心知识。

检查器拒绝以下情况：

- 出现 `wx.getClipboardData`；
- `wx.setClipboardData` 出现在未登记文件；
- 登记文件不再包含调用点；
- 运行时扫描范围包含 `dist`、测试夹具或生成索引导致报告不稳定。

报告只服务构建审计，不进入小程序主包，不上传任何剪贴板内容。

## 质量矩阵接入

在现有 v1.11 质量矩阵中增加“隐私接口”检查项。该检查只验证接口边界和调用清单，不判断微信公众平台隐私指引审核结果，也不把本地静态检查当成开发者工具正式审核结论。

## 隐私说明口径

建议在微信隐私指引中填写：

> 用于在用户主动点击“复制”“导出备份”或“复制备案地址”后，将用户当前选择的知识内容、备份文本或备案查询地址写入系统剪贴板，方便用户在本机粘贴使用。我们不读取剪贴板内容，不在后台访问剪贴板，也不会上传或保存剪贴板内容。

备份文本可能包含用户主动保存的本地笔记；只有用户主动选择复制备份时才写入剪贴板。正常浏览、启动、搜索、收藏和阅读过程中不调用剪贴板接口。

## 兼容与失败处理

- 不新增 `wx.getClipboardData`。
- 不在复制失败时读取或重试读取剪贴板。
- 复制失败只保留现有页面提示，知识正文仍可继续阅读。
- 不升级本地存储版本，不改变稳定 ID、路由、分包或云资源路径。

## 验收

- 当前运行时 `wx.setClipboardData` 调用数为 8，全部属于登记文件；
- `wx.getClipboardData` 调用数为 0；
- 审计测试覆盖通过、失败和新增未登记调用三种情况；
- v1.11 质量矩阵全部通过；
- 现有内容复制和本地备份相关检查继续通过。
