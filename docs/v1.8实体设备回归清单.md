# v1.8 实体设备回归清单

> 分支：`codex/biology-foundation-v1.8`
>
> 当前状态：模拟器已通过，实体 iPhone 与 Android 尚未执行；未完成前不得创建 `1.8.0-rc.1`、上传体验版或提交审核。

## 1. 设备准备

每台设备开始前记录：设备型号、系统版本、微信版本、开发者工具版本、测试时间和网络状态。

- iPhone：使用与正式体验接近的微信版本，允许访问小程序并能完成扫码或真机调试授权。
- Android：优先使用常见中低端机型，确认返回手势、系统字体和窄屏布局可用。
- 开发者工具：项目必须位于 `codex/biology-foundation-v1.8`，编译模式为普通编译，控制台保留完整日志。
- 云资源：先在正常网络下验证云图片签名，再切换弱网或临时断网验证文字降级；不删除云端资源。

## 2. 必测路径

两台设备都必须逐项执行并留下截图或日志证据：

| 编号 | 路径 | 通过标准 |
|---|---|---|
| A1 | 冷启动首页 | 五科入口、统计数字和底部导航可见，无白屏或重叠 |
| A2 | 生物学首页 | 6 个单元、36 个知识点、6 个方法统计与单元卡片正确 |
| A3 | `生物和细胞` 单元 | 单元封面失败时仍有标题、摘要和知识点入口 |
| A4 | `生物的基本特征` 知识点 | 核心知识、解释、例子和相邻知识点可读，长文本不横向溢出 |
| A5 | 搜索 `光合作用` | 生物学筛选保持选中，结果归属正确，点击后能进入知识页 |
| A6 | 观察聚焦 | `显微镜与细胞观察` 直接显示观察提醒、步骤、注意事项和安全处理 |
| A7 | 返回栈 | 知识点 -> 单元 -> 生物学首页 -> 首页返回顺序正确，不重复堆叠页面 |
| A8 | 收藏与最近浏览 | 保存后按 `subjectId:type:id` 打开生物学目标，不回到数学默认页 |
| A9 | 云图失败降级 | 图片加载失败后正文、标题、图示说明和操作入口仍完整可读 |
| A10 | 弱网恢复 | 恢复网络后可重试资源，不重复请求造成页面卡死或内容清空 |

## 3. 证据要求

每台设备至少保存以下证据到本地测试记录，不上传个人数据：

1. 首页、生物学首页、知识点、搜索结果和观察聚焦各 1 张截图。
2. 控制台筛选后的项目错误记录；平台云服务提示要与项目 JavaScript 异常分开记录。
3. 收藏、最近浏览和返回栈的结果说明。
4. 正常网络、弱网/断网和恢复网络三种资源加载结果。

证据文件名建议：

```text
<device>-home.png
<device>-biology-home.png
<device>-biology-knowledge.png
<device>-biology-search-photosynthesis.png
<device>-biology-observation.png
<device>-cloud-fallback.png
```

## 4. 发布门禁

只有以下条件全部满足，才允许从当前分支创建 RC：

- iPhone 与 Android 的 A1-A10 全部通过，并完成记录。
- `node scripts/check-release-readiness.js` 及当前 `scripts/check-*.js` 全部通过。
- Developer Tools 重新生成预览包体，主包和各分包大小仍低于门限。
- 云函数签名、文字降级、搜索索引和远端资源清单没有新差异。
- 工作树干净，版本号、版本描述和备案信息核对无误。

当前模拟器证据位于 `.codex-output/simulator-v18-biology/`，包括 iPhone 14 Pro Max 与 Nexus 5 的首页、单元、知识点、搜索和观察截图；这些证据不能替代实体设备记录。
