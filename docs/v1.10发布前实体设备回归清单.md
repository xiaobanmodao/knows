## 1. 回归范围

当前 `app.json` 注册了数学、英语、物理、化学、生物五个学科分包。本清单覆盖以下行为：

- 冷启动、首页导航和学科分包首次进入。
- 五科学科首页、目录/专题、知识点或方法页。
- 全局搜索、旧链接兼容、返回栈和再次进入。
- 收藏、最近浏览、笔记、阅读显示设置和本地数据保持。
- 云图正常加载、图片失败文字降级、弱网恢复和控制台项目错误。

模拟器结果只能作为开发回归证据，不能替代两类实体设备。实体设备记录必须对应本分支最终构建引用，不能沿用 `880d79b` 或其他旧版本截图。

## 3. 设备准备

每台设备开始前记录：型号、系统版本、微信版本、网络状态、开发者工具版本、构建引用和测试时间。

- iPhone：使用正式体验接近的微信版本，完成真机调试或体验版扫码。
- Android：优先覆盖常见窄屏或中低端机，检查系统返回手势和字体缩放。
- 开发者工具：项目目录必须是本分支，普通编译，控制台保留项目日志。
- 云资源：先在正常网络验证图片和文字，再切换弱网/断网验证降级与恢复；不删除云端资源。
- 本地数据：仅使用测试数据，不登录、不上传收藏、笔记或阅读记录。

## 4. 必测用例

两台实体设备都必须逐项填写模板中的 15 个用例。`passed` 必须有简短观察说明；`failed` 必须记录复现条件；未执行保持 `pending`。

| 编号 | JSON 用例 ID | 操作 | 通过标准 |
|---|---|---|---|
| A1 | `cold-start-home` | 冷启动首页 | 首页、五科入口、统计信息和底部导航可见，无白屏、重叠或项目报错 |
| A2 | `subject-math` | 进入数学 | 年级切换、章节/专题、知识点和方法模板可以打开，返回栈正确 |
| A3 | `subject-english` | 进入英语 | 册次、单元、单词/语法卡片和方法模板可以打开，长音标正常换行 |
| A4 | `subject-physics` | 进入物理 | 章节、公式、实验、图示和方法模板可读，单位与连线不截断 |
| A5 | `subject-chemistry` | 进入化学 | 主题、专题、知识点、方程式和实验入口可读，图失败不清空正文 |
| A6 | `subject-biology` | 进入生物 | 单元、知识点、观察说明和方法模板可读，窄屏无横向溢出 |
| A7 | `global-search` | 搜索跨学科关键词 | 搜索结果按学科和类型归类，点击后进入正确分包；结果无空白卡片 |
| A8 | `legacy-route` | 打开旧数学、英语、物理链接 | 缺少 `subjectId` 时仍按数学兼容，其他旧路径能跳到正确内容 |
| A9 | `package-reentry` | 首次进入分包后返回并再次进入 | 首次下载有明确加载状态；返回后页面不重复堆叠，再次进入不白屏 |
| A10 | `favorites-recent-notes` | 收藏、最近浏览、笔记 | 记录按 `subjectId:type:id` 打开正确内容，切换学科不串页 |
| A11 | `reading-settings` | 修改字号、行距和图片宽度 | 三组设置即时生效，切页和重新编译后保持，正文不遮挡固定控件 |
| A12 | `cloud-image-fallback` | 让一张云图加载失败 | 标题、正文、图示说明和操作入口仍完整可读，失败状态可重试 |
| A13 | `weak-network-recovery` | 弱网/断网后恢复网络 | 页面不死循环、不清空正文；恢复后资源可以重试并正常显示 |
| A14 | `return-stack` | 首页 -> 学科 -> 容器 -> 知识点 -> 返回 | 返回顺序与用户访问顺序一致，不跳回错误学科或重复页面 |
| A15 | `console-clean` | 过滤开发者工具平台提示 | 项目 JavaScript 错误、未捕获异常和 WXML/WXSS 错误均为 0；平台提示单独记录 |

## 5. 证据格式

证据模板位于：

```text
docs/release-regression/v1.10.0-evidence.template.json
```

实际测试时复制到本地忽略目录，例如：

```text
.codex-output/release-regression-v1.10.1/evidence.json
```

每台设备至少保存：首页、一个学科首页、一个知识点、一次搜索、一次云图降级截图，以及控制台筛选后的错误结果。截图路径写入设备记录的 `screenshotPaths`，不要把真实设备信息或个人数据提交到仓库。

证据检查：

```bash
node scripts/check-release-regression-evidence.js docs/release-regression/v1.10.0-evidence.template.json
```

当前模板允许 `pending`，只证明结构完整。实体设备完成后，用实际证据文件执行严格门禁：

```bash
RELEASE_REGRESSION_EVIDENCE=.codex-output/release-regression-v1.10.1/evidence.json \
node scripts/check-release-readiness.js --require-device-evidence
```

严格门禁要求 iPhone 和 Android 的所有用例为 `passed`、项目控制台错误为 `0`、至少有一张截图且设备型号/系统/微信版本和测试时间齐全。

严格门禁还会校验当前分支的 Developer Tools 包体报告，默认路径为：

```text
.codex-output/release-regression-v1.10.1/packages-preview.json
```

如报告保存到其他本地路径，执行前设置 `PACKAGE_SIZE_REPORT`；不能使用历史版本报告替代当前构建。

当前构建重新生成包体报告时，使用项目配置中的真实 AppID 并保留完整日志。推荐直接运行仓库脚本：

```bash
node scripts/run-release-preview.js
```

脚本会自动拒绝空报告，并将日志保存到 `.codex-output/release-regression-v1.10.1/preview.log`。如需手动执行，命令如下：

```bash
APPID=$(node -p "require('./project.config.json').appid")
/Applications/wechatwebdevtools.app/Contents/MacOS/cli preview \
  --project "$PWD" \
  --appid "$APPID" \
  --qr-format image \
  --qr-output "$PWD/.codex-output/release-regression-v1.10.1/preview-qr.png" \
  --info-output "$PWD/.codex-output/release-regression-v1.10.1/packages-preview.json"
```

如果开发者工具日志仍出现 `41002 appid missing`，先在开发者工具中确认当前登录账号拥有该 AppID 的开发权限，并重新打开项目建立绑定；不要把空文件、旧版本报告或仅显示“Using AppID”的 CLI 输出作为包体证据。

## 6. 发布前顺序

1. 在模拟器完成当前分支的五科学科入口、搜索和代表性内容路径。
2. 在 iPhone 和 Android 实体设备执行 A1-A15，填写实际证据文件。
3. 重新生成当前构建的 Developer Tools 包体报告，确认主包和全部分包低于门限。
4. 执行 `node scripts/check-release-readiness.js --require-device-evidence` 和全量 `scripts/check-*.js`。
5. 复核版本号、版本描述、备案号和云函数环境，再决定是否创建 RC/体验版。

在第 2 步完成前，普通质量检查可以继续运行，但不能把 `1.10.0` 标为 RC，也不能把模拟器结果描述为真机通过。
